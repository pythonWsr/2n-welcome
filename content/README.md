# 人物文案编辑

人物文案独立保存在 `people.json`。日常修改只改 `leaders` 中的 `name`（姓名）、`role`（角色）、`intro`（简介）；不要改 `id`、顺序、来源或 provenance。职责和简介可留空；没有可靠资料时不要补造内容。姓名不能为空，id 必须唯一。

`intro` 最多两行，用 JSON 的 `\n` 分行。手机实际换行仍需视觉验收：使用简短原义文案，不追加旧等级、Super 数量或贡献数字。显示只有姓名、角色、简介三个文字层级。成员名单 `members` 只保存已核实姓名，不附加虚构角色；人物庭院按名单原始顺序均衡分组，正常手机当前为 11 组 7 人、3 组 6 人，避免单人尾页；空名单不生成空组。分组仅用于阅读排版，不表示排名、队伍或关系；管理层姓名出现在名单中仍保留。窄屏可拆成连续阅读子窗口，但不重排、删除或改写姓名。人物介绍仍只在 JSON 中编辑。

保存后先运行 `node --test tests/people-data.test.js`，再运行 `npm run build` 重新构建，按批准的流程发布才会更新网站。当前人物版本已经用户明确授权发布到 Pages（2026-10-05）；后续人物改动先在开发分支/Sites 验收，不自动覆盖 Pages。旧 Llhleo/2n 不改。

未来文案增加汉字时需更新人物章节补充字体子集，不能替换前段已稳定字体，也不能通过手动改镜头迁就文案。庭院主文字的完整字形框使用画布 x 12%–88%、y 30%–70% 的阅读区域。成员长名可在字形边界自然折行，不改写原字符串；窄屏使用源组的连续阅读子窗口；阅读时长以当前实现为准，不把旧版本的固定 5 秒作为新要求。横竖切换通过源组与成员原始索引保留阅读位置，不能按屏幕距离重新排名。
