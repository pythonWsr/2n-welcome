# Display-atlas minification throughout the ending

The v71 phone screenshots show continued patchy Tomato surfaces and washed-out Compass needles in both the third historical event and the final crescent. v71 fixed directions but did not address this shared rendering problem.

A CPU reproduction using the actual 1024 display atlases, per-pixel UV interpolation, back-face culling and a depth buffer isolates minification. Unminified Compass -Z clearly shows the red/white needle. At mip levels 4–6 the needle mixes with nearby blue/gray atlas texels. Tomato's numerous small UV islands mix red body, green leaf and pale texels at the same levels, reproducing large discolored patches. This isolates a possible texture-atlas minification issue, but the subsequent v72 user report shows that it did not explain or resolve the observed text-triggered corruption. See 2026-10-10-petal-depth-write.md for the stronger temporal reproduction and correction. The reproduction can be rerun with scripts/qa-display-atlas.py. It is a controlled CPU comparison, not a Safari render or performance measurement.

The display sampler now clones and caches each original texture, retains its image/UV transform/flipY/color space, disables generated mipmaps and uses LinearFilter for minification and magnification. No pixel resolution or geometry reduction is introduced. GPU upload sees the configured dedicated display texture before warmup. The existing ground textures retain their samplers. Three's WebGL texture cache distinguishes minFilter/generateMipmaps, so the display clone does not replace a ground GPU sampler.

The same sampler is used by HD companionship copies (takeoff, reading ring, leaders/member surroundings and captured departure chain), all three memory chapters, and the final crescent. Companion HD installation also uses the fourteen reviewed front/up profiles, matching the existing memory correction. Cached display maps are reused during rebuild/capture/retry rather than creating a new clone each time. Their lifetime follows the cached source assets. All original GLBs, textures, loading admission/concurrency, source geometry, cameras, spatial trajectories and content remain intact.

Tradeoff: using the original atlas instead of averaged mip levels can reveal fine texture aliasing on very small moving petals. The change targets observed cross-island color contamination. A future clean atlas bake could restore safe mipmapping, but is not part of this fix.
