# 仓库维护指南

## 分支和发布边界

- `copy/2n3d-main-20261007` 是 `2n-welcome` 仓库中的 2n 3D 网站复制分支。
- `main` 属于目标仓库原有内容，本次工作只在复制分支进行。
- `.github/workflows/pages.yml` 是从源项目带来的配置，仍引用源项目的分支名和 `/2n-spatial-world/` Vite 路径。它不会因本分支提交而自动发布到目标仓库。发布前先核对目标仓库的 Pages 来源、工作流触发分支和站点路径；详见根目录 `PAGES.md`。

## 文件职责和维护边界

| 路径 | 内容与维护方式 |
| --- | --- |
| `src/` | 场景、镜头、加载与叙事运行时代码；改动时检查相关测试和资源引用 |
| `content/` | 公会人物和故事内容；遵守 `content/README.md` 中的编辑约定 |
| `public/assets/` | 模型、纹理、字体和其他网页资源；先查代码引用再删除 |
| `scripts/` | 可重跑的场景数据与模型传输构建流程 |
| `test/`、`tests/` | 自动化测试；目前测试分置于两个目录，运行命令见根目录 `README.md` |
| `studies/` | 模型和视觉研究、资源对照及检查素材 |
| `docs/resource-sources/` | 资源来源与核对记录 |
| `docs/` 下日期文档、`archive/`、`plans/`、`reviews/`、`superpowers/` | 源项目历史设计、计划、审查和发布过程，不保证反映本分支当前状态 |
| `node_modules/`、`dist/`、生成的模型传输文件 | 本地依赖或构建产物；遵守现有 `.gitignore`，不提交 |

## 清理原则

删除资源前，确认它没有运行时代码、构建脚本或测试引用。日期较早不代表文件无用：模型、字体、场景资源、内容、测试、研究材料和历史决策记录应在确认用途后再处理。过时的当前状态快照可以移除；重要的历史决策应保留并明确标注为历史。

## 本分支本轮整理

本轮移除了根目录已过时的 `CHECKPOINT.md`（Prototype 01 检查点）、`CODEX_HANDOFF.md` 和 `PROJECT_STATUS.md`（仍描述源仓库旧分支及旧发布状态），并更新根目录 `README.md`、`BRANCHES.md`、`PAGES.md` 和本目录索引。保留了网站代码、模型与资源、内容、测试、研究及有追溯价值的设计记录；没有修改 `main`，没有改动或触发部署工作流。
