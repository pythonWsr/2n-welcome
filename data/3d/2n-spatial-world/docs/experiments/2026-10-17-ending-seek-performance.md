# 结尾快滑与倒滑：排查结果和改造方案

状态：文字修复可发布；性能部分是有复现依据的设计提案，尚未实现或完成GPU/iPhone性能验收。

## 已复现的工作量

当前`createFluidClock`为确定性重放：目标tick小于当前tick就reset，再从0积分到目标。一个tick执行GPU位置、速度两个全屏pass；同时推进64个CPU观察点、320个材料引导点及门反馈。reset还重新生成262144粒子的初始位置/速度并上传纹理。

以生产时钟直接记录reset和step回调，结果如下（这是工作量计数，不是GPU计时）：

| 前一进度 → 目标 | 本次积分步数 | GPU计算pass |
| --- | ---: | ---: |
| 初始 → 90% | 777 | 1554 |
| 90% → 89% | 766 | 1532 |
| 89% → 88% | 756 | 1512 |
| 88% → 87% | 745 | 1490 |
| 85% → 100% | 162 | 324 |

微小倒滑会反复触发几乎整段重放；快速正滑会将补算集中到同一次渲染调用。调低曝光、修改粒子轨迹或仅增加滚动阻尼都不能移除这条重算路径。

## 建议：后台模拟一次，滑动按时间直接取样

保留全部262144粒子、原1/60固定积分与所有现有力、运动段落。把“生成模拟结果”和“显示任意进度”分开：

1. 进入前面的故事阶段后，以受限的后台帧预算推进模拟；每帧最多一个固定tick。每约0.25秒记录一次完整粒子位置，存为512×512 RGBA16F GPU纹理。GPU内复制，不同步读回CPU。
2. 记录同一时刻的门穿越反馈；完成后显示路径不再计算CPU观察点、材料引导点或GPU速度。初始状态对相同宽高比/动态设置只生成一次。
3. 滑动时依据目标时间查找邻近四个位置关键帧，用连续三次插值取样。由同一个展示进度驱动镜头、方框、文字、花瓣和凝形；正滑、倒滑、跳转都只改变读取时间，不重置模拟。
4. 主体进度静止时保持其状态；末尾花瓣的独立环境时钟继续运行。重播复用已完成的缓存。
5. 若准备尚未完成，停留在有明确准备状态的故事交接边界，不能一次性强制补算，不能让镜头和花瓣提前跑到尚未准备的粒子时间。优先安排在故事较早时准备以避免用户遇到等待。

### 预算和需要验证的部分

从0.18到1共有885个固定tick，步长15tick可覆盖约60张位置纹理。每张512×512×4×2=2MiB，关键帧缓存约120MiB；这不包含现有模型、渲染目标和临时模拟资源，因此必须检查iPhone峰值显存/页面存活情况。缓存就绪后释放不再使用的模拟资源。

0.25秒采样和三次插值会近似帧间轨迹，不能声称与每个固定tick完全一致。先比较门附近转弯、回中回弹、凝形前后、快滑和连续反向的偏差；必要时只在高曲率段增加关键帧密度。检查插值过冲、HalfFloat位置量化及门反馈时序。

宽高比和减少动态设置属于缓存键。变化时需受限地重建，清理旧缓存的时机应避免双份峰值和错误释放仍在显示的纹理。该兼容行为需单独设计并验收，不能静默套用错误比例的结果。

### 备选方案

- 稀疏位置+速度检查点：每1秒约8MiB，15段约120MiB；能缩短倒滑重放，但最坏仍需59tick/118pass。只有结合分帧补算与统一展示进度才可控，连续倒滑时仍可能产生可见追赶延迟。
- 全部60Hz状态：仅位置RGBA32F就约3.46GiB；加速度纹理更高，不适合本移动端站点。

建议先在独立结尾预览验证关键帧方案，再接回正式网站。验收指标应包含每次seek触发的GPU计算次数为0、连续反向轨迹连续、帧时间分布、缓存准备耗时和iPhone实际内存表现，而不只是单元测试通过。

## 同轮文字修复

新版结尾的历史文字从3秒缩短为0.75秒的五次平滑淡出；正nextT期间不写入深度缓冲，避免透明文字切掉后渲染的花瓣。opacity为0时group隐藏且readingBounds清空。此前故事和旧结尾的深度策略/时序保留；正反向使用同一绝对进度取样。
