# 加载提速与自动播放交接

## 本轮目标与边界

优先修复加载阶段 11–23 缓慢的问题，并添加默认关闭的自动播放。原始模型、高清展示资源、贴图、花瓣数量、地面姿态、相机路线、自在飞行和汇聚旋转全部保留。仅更新 `experiment/lookback-v2` 与原 Sites；不得改 main、旧仓库或 GitHub Pages。

## 已实现

- 构建时运行 `scripts/bake-petal-placement.mjs`，用原 GLB POSITION、原地形函数、原同步摆放算法生成 36 个手机/桌面物种组合的精确实例矩阵。
- Desert、Ocean、Jungle、Hell 和沿海 Sand 的运行时安装直接恢复矩阵；保留原几何与材质。几何签名不匹配、缓存缺失或地形上下文不一致时回退原算法。
- Desert 地形上下文使用稳定键，不依赖会被打包器改变的函数源码。每次生产构建重新生成全部缓存，防止算法改动后遗留旧矩阵。
- Garden 原摆放保持不变。未减面、未降贴图分辨率、未减少实例、未降低像素比，未跳过资源和 GPU 预热。
- 加载状态分别显示地面花瓣 23 项、高清花瓣 14 项以及完整画面预热阶段，避免高清下载被隐藏在 23 项进度之后。
- 全部资源与 GPU 就绪后，右下角显示自动播放按钮；默认关闭。从当前位置继续，手动触摸/滚轮/导航键接管即暂停，终点停止，不自动重播。
- 开启/关闭后 1.4 秒淡为半透明；点击/键盘聚焦时清晰。保留 44px 点击高度、状态语义与 iPhone 安全区；触屏不使用易粘滞的 hover 状态。
- 切到后台不会累计推进时间（复用现有暂停渲染及恢复计时机制）。全程以约 180 秒为基准；中途启用只播放剩余部分。

## 验证

- 真实 GLB、两种设备规格的全部缓存矩阵与原同步算法逐项 Float32 完全一致。
- 本地 Hell 手机 288 实例比较：缓存路径约 15.2ms、0 次让帧；原算法模拟 60Hz 调度约 10.86 秒、517 次让帧；矩阵完全相同。此结果不是 iPhone Safari 的真实加载耗时，也不涵盖网络下载。
- 生产构建成功。既有大于 500kB 的 chunk 提示仍存在；新增缓存约 620kB 原始文本，压缩后远小于原高清资源体积。
- 发布前运行完整 `node --test test/*.test.js tests/*.test.js`，并核对 Git 差异与资产保持。
- 未进行真实 iPhone Safari 的视觉/触摸验收，不能以单元测试或部署成功代替实际设备确认。
